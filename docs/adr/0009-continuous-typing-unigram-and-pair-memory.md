# 速成和倉頡的連打：用現有的字頻和詞頻組句，加上手機上的搭配記憶，不打包搭配表

開了連打（設定，預設關閉），速成和倉頡可以不選字、連續打幾個字的碼，候選列出整句候選，例如 hivddpof 出「我好想你」。引擎把組字拆成拆碼格：每個字的碼是一條邊，相連的字剛好是 words.hk 的詞就多一條詞的邊；然後用 k-best Viterbi 取分數最高的一句。分數只用字庫現有的 words.hk 字頻和詞頻，當作同一個 unigram，字的次數先扣除它在詞裏出現的次數。再加上搭配記憶：開了連打之後，使用者寫入的中文裏前後相連的兩個字記下次數，只存在手機上；組句時，記下的搭配加分，組字前面那個字（上文）和第一個字的搭配也算。開了連打，速成三個字母以上就不再一定是英文，所以組字像英文時不出整句。

## Considered Options

- 不做：速成三個字母以上一定是英文，中英混打最簡單；但使用者要逐個字選，Gboard 已經訂下期望。
- 只做詞語連打（整串剛好是一個詞才出）：最安全，但省得最少（一句話很少剛好是一個詞），而且同樣要判斷英文。
- 加入粵文維基百科的前後字搭配表（CC BY-SA 4.0，要獨立成檔，ADR 0004）：長句準確了一些；但字庫要大幾 MB，而且百科文體會把口語句子帶偏。不加。
- 用 words.hk 詞裏面相連的字當作上文的搭配：不用新資料，但試過反而更差，因為詞裏的搭配已經在詞的邊計過一次。
- 用字母三連模型判斷英文：誤判可能較少，但要另外建模型和量度。第一版只用英文詞庫加詞尾規則，試用之後再決定。
- 用 librime，或 Rime 的 essay、octagram 資料：違反 ADR 0004（不寫 C++）和 AGENTS.md（LGPL）。

## Consequences

- 準確度：倉頡的碼長，整句大多一次就對；速成重碼多，經常要改選。搭配記憶令打過的句子再打時準確得多，對未打過的句子沒有明顯的壞影響。速成會猜錯，設定的說明要寫清楚。
- 組字剛好是速成或倉頡的一個碼時照舊，次序和位置不變，靠固定位置打字的熟手不受影響。整句候選排在用盡全部字母的候選字（例如粵拼的「你好」）後面，之後是只用前面字母的粵拼字詞、開頭部分的詞和字。選了開頭部分就分段寫入（ADR 0008），其餘字母再組句。
- 判斷英文：英文詞庫的字或任何字的開頭、去掉詞尾後是英文詞庫的字（cats、happened），或第二個字母起有大寫。英文詞庫沒有的人名和網上用語（cheung、haha、lihkg）仍然會出整句候選。「寫英文」空白鍵模式下空白鍵照樣寫入英文；「選中文」模式下空白鍵會寫入整句候選，要按英文建議才寫入英文。
- 標點和 Enter 的規則不變（ADR 0003）：有組字時按標點，字母照舊當英文寫入。
- 整句候選不記錄成記憶字。搭配記憶跟記憶字的規則：只存在 noBackupFilesDir，不備份；記憶字關了、密碼欄位和要求不學習的欄位都不記錄，記憶字關了也不加分；「清除全部記憶」一併清除。最多 20,000 對。
- 碼表、字詞的分數和詞的索引在背景執行緒載入記憶體，開了連打會多用一些記憶體，啟用倉頡比只啟用速成多。每打一個字母整句重算，在電腦上量度不到一毫秒。字庫和授權不變。
- 使用統計多報一個設定：連打開了沒有。
- 預設開啟、字母三連模型、授權合適的搭配資料，要等試用之後再決定。
