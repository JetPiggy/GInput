# 英漢詞典預設開啟，用 words.hk 的英粵對照表，放進字庫，在手機上查

取代 ADR 0011：資料、位置和規則不變，只是改為預設開啟。

英漢詞典是設定，預設開啟：打完整個英文字時，候選列在候選字和英文建議之間列出最多 3 個譯詞，例如 duck 出「鴨」。資料用 words.hk 分析檔的英粵對照表（公有領域）：它由 words.hk 詞條的英文解釋整理出英文字對應的粵語字詞，用香港的寫法和講法，例如 taxi 出「的士」、cheese 出「芝士」。建置時把英文詞庫的每個字連同它的詞幹對上，按相關度和 words.hk 的字頻、詞頻排，再用 GInput 自行整理的清單修正常用字、略去粗口，放進字庫的一個新表。手機上只查表，不連線，不送出任何東西。

預設開啟，是因為中英混打的人最常想要的正是這個：打 duck 就可以揀「鴨」，不用切換輸入方案，也不用另開翻譯。代價是英文建議會被推後最多三格；但空白鍵照樣把組字當英文寫入，照打的字母仍然是英文建議的第一項，打英文的手勢不變。不想要的人可以在設定關掉。

## Considered Options

- 預設關閉（ADR 0011 的決定）：英文建議的位置不變，但大部分人不會發現這個功能。
- 譯詞排在英文建議後面：英文建議不會被推後，但只啟用速成時，譯詞常常要向右捲才看到。
- CC-CEDICT（CC BY-SA 4.0）：照 ADR 0004 可以獨立成檔使用，但它是中文對英文、以普通話為主，反轉之後很雜，香港講法也排得後（例如 chocolate 先出「巧克力」）。
- Wiktionary 的翻譯表（CC BY-SA 4.0 加 GFDL）：分了粵語和普通話，但粵語的覆蓋較少，又要多一個 CC BY-SA 的檔案。
- Wikidata（CC0）：名詞的香港標籤很好，但沒有動詞和形容詞，詞義也會對錯。日後可以用來補充名詞。
- ECDICT（寫明 MIT）：釋義的來源不清，部分可能來自標為 GPL 的詞典，而且是簡體。PanLex：授權的說法互相矛盾。都不用。
- 手機上的翻譯模型（ML Kit、Firefox Translations）：ML Kit 是專有的；Firefox 的模型太大，也沒有粵語；逐個字查用不着。
- 經伺服器翻譯：每打一個字都要送出輸入內容，違反 ADR 0005。

## Consequences

- 字庫升一個版本，多一個英漢詞典的表，大約大 1 MB。words.hk 是公有領域，可以和其他資料放在同一個檔案，不用獨立成檔；開源授權頁的 words.hk 一項加上這個用途。
- 只在組字最少三個字母、是英文詞庫的字（或者去掉詞尾後是）時才出：打到一半的字不出；兩個字母的組字在速成一定是碼，譯詞會排在很後，沒有用處。組字本身是英文詞庫的字就只查它，不再去詞尾（peter 不會出 pet 的譯詞）。
- 速成、倉頡和粵拼的候選字次序和位置不變，譯詞排在它們後面。空白鍵不會選譯詞，「選中文」模式下打英文按空白鍵照樣寫入英文。
- 譯詞不記錄成記憶字：記憶字按字記錄，會改變速成和倉頡打同一個字時的次序。
- words.hk 的譯詞有錯，例如只是詞的一部分的單字、別的詞義，也有粗口；預設開啟之後人人都會看到，所以 GInput 自行整理的兩份清單先修正最常用的大約 1,500 個英文字和香港常打的字，之後逐步補充。
- 不送出任何輸入內容，ADR 0005 不用改。使用統計加報這個設定和按譯詞的次數，只有次數。
- 兩個字以上的英文詞、記住每個英文字選過的譯詞，日後再決定。
